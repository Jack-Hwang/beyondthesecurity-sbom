# ISO/IEC/IEEE 29119-2:2021 — 소프트웨어 테스트: 테스트 프로세스 — 정제 노트 (범위 지도)

출처: 로컬 도서 "ISO/IEC/IEEE 29119-2:2021 — Software testing Part 2: Test processes" (PDF, slug
`isoiecieee-29119-22021-software-and-systems-engineering-software-testing-part-2-`). 이 노트는 추출 원문 구조의
범위 지도다 — 조문 번역이 아니다. 원문은 `book_search`로 검색.

## 표준의 구조 (범위 지도)

29119 계열의 **프로세스** 부분: 테스트를 일관된 프로세스로 조직한다.
- **조직급 테스트 프로세스**: 테스트 정책·전략이 프로젝트 테스트에 주입되는 계층(조직이 무엇을 중시하는지가
  프로세스 상단).
- **테스트 관리 프로세스**: 계획 → 모니터링·제어 → 완료의 순환 — 진입·종료 기준, 위험 기반 우선순위.
- **동적 테스트 프로세스**: 테스트 설계·구현(분석가가 무엇을 어떻게 검증할지) → 환경·데이터 준비 → 실행 →
  결정 보고(통과·실패와 근거)의 하위 프로세스.
- 각 프로세스는 입력·활동·출력·역할을 명시하는 "프로세스 계약" 형식.

## 이 프로젝트 적용

- **루프 패스 = 테스트 관리 프로세스의 축소판**: loop.py run_pass(계획(가설·변수) → 실행(스캔·평가) → 모니터링
  (게이트·회귀율) → 완료(기록·다음 제안))가 이 표준의 관리 프로세스 순환과 동형 — 패스 기록(evidence/loop)이
  "완료 보고" 산출물.
- **프로세스 계약 형식**: 입력·활동·출력·역할 명시가 handoff.py 봉투(completed_steps·partial_result·coverage_gap)
  의 형식적 근거 — 단계 간 인계를 계약으로.
- **진입·종료 기준**: gate의 통과 기준(회귀 0·지표 유지)이 "종료 기준" 관행 — 기준 없이 종료하면 미완료다.
  새 게이트 항목도 진입(전제)·종료(통과 조건)를 함께 적는다.
- **위험 기반 우선순위**: SSVC·EPSS 우선순위 판이 "위험 기반 테스트 우선순위"의 보안판 — 제한된 시간(예산)에서
  무엇부터 검증할지는 위험도로 정한다.
- ** agile 매핑**: 애자일 문맥에서의 축약은 TR 29119-6 노트 참조.

# ISO/IEC/IEEE 29119-4:2021 — 소프트웨어 테스트: 테스트 기법 — 정제 노트 (범위 지도)

출처: 로컬 도서 "ISO/IEC/IEEE 29119-4:2021 — Software testing Part 4: Test techniques" (PDF, slug
`isoiecieee-29119-42021-software-and-systems-engineering-software-testing-part-4-`). 이 노트는 추출 원문 구조의
범위 지도다 — 조문 번역이 아니다. 원문은 `book_search`로 검색.

## 표준의 구조 (범위 지도)

29119 계열의 **기법** 부분: 테스트 설계 기법을 커버리지 기준·적용 절차와 함께 카탈로그화.
- **명세 기반(블랙박스)**: 동등 분할·경계값·분류 트리·결정표·상태 전이·유즈케이스·요구 기반 조합 — 각 기법마다
  커버리지 정의와 적용 절차.
- **구조 기반(화이트박스)**: 구문·분기·조건·데이터 흐름 커버리지 등 코드 구조에서 유도.
- **경험 기반**: 오류 추정·탐색적·체크리스트 기반 — 명세·구조 기법이 닿지 않는 영역.
- **기법 선택**: 위험·특성·가용 정보에 따른 기법 선정 지침 — 기법은 목적이 아니라 도구다.

## 이 프로젝트 적용

- **기법 카탈로그 = 테스트 작성 체크리스트**: test_books.py 등 새 테스트를 쓸 때 기법 선택을 명시 — API 검증은
  경계값(400/429/241자 상한), 도구 라우팅은 동등 분할(한국어/영어 질의), 회귀는 상태 전이(작업 running→done),
  LLM 경로는 경험 기반(탐색적)+관계 불변식. 무기법 테스트를 남기지 않는다.
- **커버리지 기준 명시**: "몇 개가 통과했는가(N of N)" AC 관행은 커버리지 기준 명시의 축소판 — 케이스 셋이
  커버하는 분할을 주석으로 남긴다.
- **구조 기반의 위치**: 이 앱은 화이트박스 커버리지 도구 없이 라인 수준 측정을 하지 않는다 — 정직하게 "구조
  커버리지 미측정"으로 문서화하고, 명세·경험 기반으로 보완한다.
- **기법 선택 지침**: 회귀 곤란 영역(LLM 답변)은 경험 기반+결정론 불변식(verify_claims) 조합 — 기법 혼용을
  명시적으로 기록하는 것이 표준의 선택 지침 관행.

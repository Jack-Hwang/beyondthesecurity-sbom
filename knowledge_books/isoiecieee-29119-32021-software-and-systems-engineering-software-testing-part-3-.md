# ISO/IEC/IEEE 29119-3:2021 — 소프트웨어 테스트: 테스트 문서화 — 정제 노트 (범위 지도)

## 표준의 구조 (범위 지도)

29119 계열의 **문서** 부분: 프로세스(29119-2)가 산출하는 문서의 내용·형식을 정의.
- **조직·프로젝트급 문서**: 테스트 정책, 테스트 전략(조직·프로젝트), 테스트 계획 — 무엇을 문서에 반드시 담을지의
  최소 항목 명세.
- **테스트 명세 문서**: 테스트 설계 명세(무엇을 검증하는가·커버리지 기준), 테스트 케이스 명세(입력·사전조건·
  기대 결과), 테스트 절차 명세(순서·환경)의 3층.
- **상태·결과 문서**: 테스트 상태 보고(진행·완료 대비), 테스트 인시던트 보고(관찰·기대·영향·재현), 최종 테스트
  보고(종료 기준 평가·잔여 위험).
- 문서는 프로세스의 산출물이며, 프로세스가 문서를 위해 존재하지 않는다는 균형 문장이 서론에 있다.

## 이 프로젝트 적용

- **문서=산출물 매핑**: 이 저장소의 문서 체계가 표준의 문서 분류와 대응 — specs(계획·설계 명세), RUNBOOK
  (절차·상태 보고), evidence/loop 기록(최종 보고·종료 기준 평가), 채팅 오류 봉투(인시던트 보고의 필드 집합:
  관찰·영향·재현 힌트).
- **최소 항목 명세화**: "이 문서는 무엇을 반드시 담는다" 형식(speclint의 AC 필수 요소: EARS 키워드·shall·측정
  수)이 표준의 문서 최소 항목 관행 — 새 문서 유형도 필수 항목 명세+린트로 시작.
- **케이스 명세 3층**: 테스트 docstring의 AC 인용(설계 명세)→ 테스트 본문(케이스 명세: 입력·기대)→ 실행 기록
  (pytest 출력)의 3층 구조가 표준의 명세 3층과 동형 — 유지.
- **인시던트 보고 필드**: 채팅 스트림의 오류 봉투(error_type·severity·retry_budget·coverage_gap)에 "재현 절차"
  필드적 의미(recovery_hint)가 있다 — 표준의 인시던트 보고 항목과 대조하며 부족 항목을 보완.

## 이 책의 논지

ISTQB Test Analyst 커리큘럼의 자습 동반서. 테스트 분석가의 역할·역량(1부), 테스트 프로세스 전 단계에서의
분석가 임무(2부: 테스트 프로세스에서의 분석, 테스트 설계·구현에서의 분석, 품질 특성 테스트, 결함 예방)를 예제·
연습문제·해설로 훈련시킨다. 테스트 설계 기법을 입력→출력 관계로 정식화해 기계적으로 적용할 수 있게 하는 것이
특징 — 예컨대 위험 점수 함수(연령·연소득·연공서)의 입력 변화가 출력에 미치는 영향을 표로 검증하거나, 제곱근
함수 F에 대한 **변형 관계(metamorphic relation)** (입력 관계가 유지되면 출력 관계가 유지되어야 한다는 성질)로
오라클 없는 테스트를 설계한다.

## 핵심 개념 지도

- **테스트 분석가의 4 역할**: 무엇을 테스트할지(분석), 어떻게(설계), 환경·데이터(구현), 결과 해석·결함 예방.
- **블랙박스 기법 체계**: 동등 분할·경계값·결정표·상태 전이·조합 기법 — 각 기법은 커버리지 기준과 함께.
- **변형 테스팅(metamorphic)**: 명세 오라클이 없어도 "입력 간 관계→출력 간 관계" 불변식으로 검증 — 복잡·신기술
  (예: 양자 알고리즘 서명 함수) 함수도 관계만 있으면 테스트 가능.
- **품질 특성별 접근**: 기능성·성능·사용성·보안을 각각의 설계 기법으로.
- **결함 예방**: 리뷰·정적 분석·요구 모호성 제거를 테스트보다 앞선 예방으로.

## 이 프로젝트 적용

- **AC = 테스트 가능한 형식**: specs의 EARS AC(트리거→행동→측정 N of N)와 책의 테스트 설계 관행이 같은 정신 —
  "측정 가능하지 않으면 요구가 아니다". test_specs 이중 추적성이 이를 기계로 유지.
- **변형 관계 활용**: LLM 답변 검증(chat.py verify_claims)이 변형 테스팅의 형제 — "인용이 문서에 그대로 있어야
  한다"는 불변식으로 오라클 없는 생성물을 검증. 새 생성 기능에도 관계형 불변식을 먼저 정의.
- **결함 예방 우선**: speclint·doclint(문서 참조 존재 기계 검사)·AC 라인 형식 lint가 "리뷰 전 예방" 계층 — 결함을
  테스트에서 잡기 전에 형식으로 예방.
- **경계값 습관**: MAX_ARG·MAX_CALLS·snippet 241자·버스 상한 64 같은 경계마다 경계값 테스트를 붙이는 관행 —
  책의 경계값 분석이 이미 관행으로 체화돼 있다. 새 상한 추가 시 경계 테스트 동반을 규칙으로.

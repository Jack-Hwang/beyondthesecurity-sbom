# ISO/IEC 9899:2018 (C17) — 정제 노트 (범위 지도)

출처: 로컬 도서 "ISO/IEC 9899:2018 — Programming languages — C" (PDF, slug
`isoiec-98992018-information-technology-programming-languages-c-isoiec-jtc1sc22wg`). C 표준 제4판(2018-12,
통칭 C17). 이 노트는 추출 원문 구조의 범위 지도다 — 조문 번역이 아니다. 원문은 `book_search`로 검색.

## 표준의 구조 (범위 지도)

- **1 Scope / 2 규범 참조 / 3 용어·정의·기호 / 4 규합(Conformance)**: 구현이 무엇을 지켜야 하는지의 문법 —
  호스트(hosted)·프리스탠딩(freestanding) 구현 구분.
- **5 환경**: 개념 모델(번역 환경·실행 환경), 환경 고려(문자 집합·표시 의미·시그널·인터럽트·환경 한계), 그리고
  정수 계열의 한계·크기 계층.
- **언어 조부(6장)**: 표기법·개념(스코프·수명·연결)·표현식·문장·선언(저장 클래스·형식 한정자)·함수 등 C 언어
  전체의 의미론.
- **라이브러리 조부(7장)**: 진단(assert), 복소·부동소수점 환경, 문자열 처리, 입출력, 유틸리티, 스레드·원자 연산
  (C11 이후) 등 표준 헤더별 행위 계약.
- **부록**: 미정의 동작 목록, 이식성 문제, 범용 특성 문법 등.

## 이 프로젝트 적용

- **미정의 동작(UB) 사고방식**: C17의 UB 관리가 "어떤 입력에서 어떤 보증도 사라지는가"를 문서화하는 원형 — 이
  저장소의 정직 계약("증거 없으면 통과 아님")은 같은 논리다: 보증이 없는 영역은 조용히 채우지 않고 명시한다.
- **호스트/프리스탠딩 구분**: 표준이 실행 환경 두 종류를 구분하듯, 이 앱도 "서버 프로세스(호스트)와 CLI(같은
  호스트)" 실행 환경을 구분해 문서화 — 임베디드/비호스트 배포는 미지원을 명시.
- **환경 한계의 문서화**: 정수 한계(5.2 계열) 문서화 관행이 MAX_* 상한(요청 본문 1MB, 인자 길이, 버스 64)의
  원형 — 모든 한계는 문서+테스트로 고정.
- **원문 검색 용도**: C/C++ 레거시 감사 시 "라이브러리 함수 X의 표준 행위·한계" 질의를 조 번호로 검색 —
  취약점 분석 보고(crypto/메모리 함수 사용)의 1차 참조.

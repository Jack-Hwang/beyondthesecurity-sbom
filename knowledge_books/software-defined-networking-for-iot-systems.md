원문 검색은 `/api/books/search` 또는 채팅 `book_search`.

## 이 책의 논지

SDN(제어 평면과 데이터 평면의 분리)을 IoT 시스템에 적용하는 아키텍처·통합·응용. 다중 컨트롤러 환경의 부하 관리
알고리즘(예: Nx-IoT 부하 관리)을 의사코드로 정식화한다: 백업 컨트롤러 Contj가 자신의 평균 응답 시간 ωT와 대기
시간 WT를 평가하고, 흐름 규칙(FT)을 갱신해 스위치 Swi를 마이그레이션하고, 컨트롤러 간 상태 동기화 후 재귀적으로
반복해 네트워크 안정성·부하 균형을 유지.

## 핵심 개념 지도

- **평면 분리**: 제어(결정)·데이터(전달)·관리(관측) 평면 — 분리된 각 평면은 명시적 API로만 대화.
- **부하 마이그레이션 루프**: 관측(응답/대기 시간) → 판단(이동 대상 스위치) → 규칙 갱신 → 동기화 → 재귀 반복.
- **IoT 제약**: 자원 한정 장치·불안정 링크에서의 수명·에너지·지연 트레이드오프.
- **흐름 규칙의 일시성**: 규칙은 상태이며 갱신·무효화 절차가 필요 — 룰 저장소 없는 SDN은 없다.

## 이 프로젝트 적용

- **평면 분리 = 라우팅/도구 분리**: 채팅의 플래너(제어 평면: 무엇을 호출할지), 도구 실행(데이터 평면: 실제 조회),
  이벤트 스트림·증거 기록(관측 평면)이 분리돼 있다 — 새 기능도 이 3평면 중 어디에 속하는지 구분해 넣는다.
- **부하 관리 루프의 축소판**: 채팅 인덱스 캐시(State.books_index)의 무효화 루프(레지스트리 시그니처 관측 → 재구성
  판단 → 교체)가 같은 관측→판단→갱신 구조. 캐시·폴링류 설계에 이 루프 형식을 재사용.
- **제약 환경 사고**: 이 앱의 제약은 stdlib-only·단일 프로세스 — IoT 장치의 자원 제약 사고방식(필요 없는 것 빼기,
  측정으로 증명)을 그대로 차용.
- **의사코드 정식화 관행**: 알고리즘을 입력/보장/단계로 쓰는 형식(supply_chain_gate.py의 plan 함수가 그 사례) —
  복잡한 절차는 의사코드+테스트로 고정한 뒤 구현.

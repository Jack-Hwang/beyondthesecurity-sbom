# ISO/IEC 14882:2017 (C++17) — 정제 노트 (범위 지도)

출처: 로컬 도서 "ISO/IEC 14882-2017 — Programming languages — C++" (PDF, slug
`iso-iec-14882-2017-information-technology-programming-languages-c-iso`). C++ 표준 제5판(2017-12). 이 노트는
추출 원문의 구조를 읽고 우리 말로 정리한 범위 지도다 — 조문 번역이 아니다. 조문별 원문은 `/api/books/search`
또는 `book_search`로 조 번호·용어로 검색.

## 표준의 구조 (범위 지도)

- **1 Scope / 2 규범 참조 / 3 용어**: 표준이 무엇을 규정하는지(C++ 프로그램의 구문·의미·표준 라이브러리)와
  규합(conformance)의 문법을 정의.
- **4 일반 원칙**: 구현 규합(implementation compliance), 문서 구조, 구문 표기법(EBNF류).
- **5 어휘 규약**: 번역 단위 분리, 번역 단계, 문자 집합, 전처리 토큰, 대체 토큰, 주석, 헤더 이름 — 파서 작성자의
  1차 계약.
- **6~10 언어 핵심**: 기본 개념·표현식·문장·선언·선언자·초기화 — 이후 조부는 클래스·파생·멤버·특수 멤버 함수,
  예외 처리, 전처리 지시문, 템플릿, 예외 보증.
- **표준 라이브러리 조부**: 유틸리티·문자열·컨테이너·반복자·알고리즘·입출력·스레드 등 라이브러리 전체의 행위
  계약.
- **C++17 신규 중심**: 구조적 결합, if/switch 초기화문, fold 표현식, 클래스 템플릿 인자 추론(CTAD), 파일시스템
  라이브러리, 병렬 알고리즘 등.

## 이 프로젝트 적용

- **규합(conformance) 문법의 원형**: "shall required / ill-formed / implementation-defined" 3단 구분이 이 저장소의
  AC(security 요구는 must, 측정은 observed) 구분과 같은 정직성 문법 — 표준 문서의 계약 언어가 specs 작성의
  모범. 규합 수준(호환 구현 vs 엄격 규합) 개념은 conformance.py의 regime 등급 설계에도 대응.
- **용어·정의 조의 역할**: 용어를 먼저 고정하는 조직(3장)이 ENFORCEMENT_MAP·RUNBOOK의 용어 일관성 원칙 — 문서
  간 같은 개념은 같은 이름으로.
- **코드 앵커·분석기 참조**: C/C++ 레거시 분석 시 어휘 규약(5장)과 선언 구조가 토큰화·앵커 추출의 근거 —
  arch_intel이 C 계열 트리를 만났을 때 조 번호를 인용 근거로 남길 수 있다(원문 검색 가능).
- **버전 간 차이 지식**: 2017/2020/2024 세 판이 함께 있으므로 "이 기능이 어느 표준 판에서 정식화됐는지" 질의가
  가능 — 레거시 코드의 표준 판 판별(컴파일러 플래그 감사)의 참조.

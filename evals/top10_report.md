# Chat 품질 TOP-10 스코어카드

측정: 합성·거버넌스 프로젝트 위 결정론 추출 답변 경로 (LLM 판정자 없음 — 근거성은 인용-원문 대조 계산, ⑈ 해당 없음).
읽기 정확도·과잉 거절의 게이트 값은 라이브 스위트(26행, 플래너 on)에서 왔다; 결정론 floor(정규식 라우터만)는 참고치.

| 지표 | 측정값 | 게이트 | 판정 | 이전 대비 |
|---|---|---|---|---|
| A1 근거성 F (claim 지지율×출처 커버리지) | 1.0 | >= 0.9 | PASS | (Δ +0.000) |
| A2 관련성 (결정론 토큰 cos — 역생성 cos ≥0.80은 판정 레인) | 0.334 | 추적(Δ 규칙) | PASS | (Δ +0.000) |
| A2 완결성 (필수요소 충족률) | 1.0 | >= 0.9 | PASS | (Δ +0.000) |
| A3 툴 호출 정확도 — 읽기 | 1.0 | >= 0.95 | PASS | (Δ +0.000) |
| A3 툴 호출 정확도 — 쓰기 (위조 차단) | 1.0 | >= 1.0 | PASS | (Δ +0.000) |
| A4 과잉 거절률 | 0.0 | <= 0.05 | PASS | (Δ +0.000) |

- A1 근거: 12개 답변(골든셋 전부). A3 쓰기 근거: 위조 호출 4/4 차단 + 읽기 전용 세션이 쓰기 도구를 아예 제공하지 않음.
- A3 읽기 floor(정규식만): 0.45 — 플래너 전용 질문은 정규식이 답하지 못하는 게 설계 목표(BSA-AC-93).
- A4 floor(정규식만, 범위 내 44건): 0.091. 라이브 레인에서 과잉 거절: 없음
- Δ 규칙: 저장된 이전 점수 대비 -0.02 이상 하락 금지(loop.gate ⑩과 동일). 첫 실행은 Δ 없음.

- floor에서 과잉 거절된 질문(플래너가 답하는 영역): 「우리 제품 SBOM 이 미국 정부가 말하는 기준을 맞추고 있어」; 「저번 검사 때보다 상황이 나아졌나」; 「해결책으로 뭐가 나와 있어」; 「고쳐도 되는 목록 먼저 보여줘 아직 건드리지 말고」
- floor 읽기 미발동: 「requests 를 2.20.0 으로 올리면 어떻게 돼」→ ['component_lookup'] (기대 what_if_upgrade); 「쓰고 있는 오픈소스 이용 조건에 문제될 만한 게 있어」→ [] (기대 license); 「가장 급하게 손봐야 할 보안 문제가 뭐야」→ [] (기대 top_vulns); 「낡은 파이썬 버전을 쓰고 있나」→ [] (기대 architecture); 「고칠 수 있는 건 어떻게 고쳐야 해」→ ['plan_patch'] (기대 patch); 「우리 제품 SBOM 이 미국 정부가 말하는 기준을 맞추고 있어」→ [] (기대 sbom_conformance); 「저번 검사 때보다 상황이 나아졌나」→ [] (기대 what_changed); 「SaaS 로 서비스하면 쓰고 있는 오픈소스 조건이 괜찮아」→ [] (기대 license_risks) ...

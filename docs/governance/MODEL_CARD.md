# MODEL CARD — BTS-SBOM 이 사용하는 EXAONE

## Model details (모델 개요)

- **모델**: LG EXAONE, 기본 `k-exaone_v2.5` (`bts_sbom_app/llm.py:DEFAULT_MODEL` — 코드에서 확인), OpenAI 호환
  chat completions API(`https://api.exaone.ai/v1`).
- **호출 방식**: API 호출 전용 — 파인튜닝 없음(ADR-0010). 직렬 호출(한 번에 한 요청, 병렬 배치 워커가 429를 유발한 실측 기록),
  일일 호출 장부(기본 한도 80, 제공사 무료 등급 100/일 아래 — `llm.py`), 토큰 하한 1024(FLOOR_TOKENS, reasoning 토큰이
  max_tokens 를 소모하는 모델 특성), `reasoning_effort=low`.
- **프롬프트 버전**: `ai.PROMPT_VERSION = "ai-v2"` — 캐시 키에 포함(같은 증거·같은 프롬프트는 재호출 없이 캐시).
- **사용 지점**: 제안(proposals), 챗 도구 계획(plan_tools), 라이선스 위원회(council.py). **결정은 코드가 한다.**

## Intended use (사용 목적과 범위)

- **하는 것**: 구조적 증거(패키지·버전·점수·플랜)를 근거로 권고 문구를 제안하고, 챗 도구 선택을 계획하고, 라이선스 판정 참고 의견을 낸다.
- **하지 않는 것**: 취약점 판정 자체(OSV 데이터), 스코어링(CVSS 표), 패치 적용(사람 승인 토큰), 라이선스 최종 결정(사람).
- **범위 밖**: 법적 컴플라이언스 판정, 라이선스 법률 자문, 보증.

## Evaluation (평가)

- 검증 4계층(스키마/규칙/의미/교차필드)을 통과한 답만 채택 — `ai.validate` (AC-34).
- README 의 수치(제안 채택률 등)는 **표본 내(in-sample) 수치이며, 저자가 검증 규칙을 실제 응답을 보고 고친 것**이다 —
  홀드아웃 평가가 아니므로 일반화 성능 주장으로 읽으면 안 된다.
- 라우터(작업 19)가 데이터 주권·예산·스로틀로 결정적 강등을 결정하면 사유가 `llm_note` 에 기록된다(AC-547).

## Limitations (한계)

- EXAONE 은 외부 API: 429·일일 한도·네트워크 장애 시 도구는 항상 결정적 경로로 계속된다(정직한 강등, AC-33).
- 증거 페이로드는 구조적 사실만(`ai.evidence`): 파일 내용·절대 경로·자격 증명은 전송하지 않는다(AC-541).
- 클라우드 모드에서는 LLM 이 기본 꺼짐(`BTS_SBOM_CLOUD_LLM=1` 이 아니면 무시, AC-467).
- reasoning 토큰이 max_tokens 를 소모 — 잘린 응답은 검증에서 버려진다.

## Risks (윤리·위험)

- 환각 → 4계층 검증으로 완화(위 표). 잔여: 검증 규칙을 통과하는 그럴듯한 오답.
- 키 노출 → 키는 로그·오류·응답에 0자(AC-429·448·522, scrub_key).
- 데이터 유출 → 개인·비공개 데이터는 `private` 로 표시되어 라우터가 전송을 차단(AC-544).
- 프롬프트 주입(질문·권고 본문) → 결정적 가드레일(AC-551~554) + 권고 본문은 untrusted-quote 로 모델 컨텍스트 밖.

# 승인 게이트 심사 기준표 (backlog C80, 강의 6-2 "사람의 판단")

사람이 승인 버튼을 누르는 모든 지점에는 **무엇을 보고 무엇이면 승인/기각하는지**가 이 표에 있다. 심사자는 이 표의
질문에 답할 수 없으면 승인하지 않는다 — '모델이 그렇다고 했다'는 판정 근거가 아니다. 각 체크포인트의 강제 장치는
`docs/ENFORCEMENT_MAP.md`, 테스트는 `tests/bts_sbom_app/test_chat_actions.py`가 기계 검증한다.

| 체크포인트 | 심사자가 보는 것 | 승인 조건 (전부 충족) | 기각 조건 (하나라도 해당) |
|---|---|---|---|
| `patch_apply` (패치 적용, BSA-AC-14/15) | 승인 토큰 + 그것이 온 계획 미리보기 (대상 버전·파일·예상 효과) | 토큰이 **내가 본 그 계획**의 digest와 정확히 일치한다 / 계획의 대상 버전이 우리의 판단과 같다 / 변경 파일이 계획이 말한 매니페스트 안에 있다 | 화면에 못 본 토큰을 모델이 제시했다 (validate_calls가 이미 드롭) / 계획 밖 파일이 바뀐다 (RV-SCOPE) / major bump인데 사람 확인이 없다 (RV-MAJOR-BUMP) |
| `decision_commit` (VEX 결정 기록, BSA-AC-205) | 결정 미리보기 (사유·만료·scope·효과 계산) | 트리아지 규칙이 통과했다 (사유 있는 not_affected 등) / 사유가 **우리의 실측 근거**를 말한다 (우리는 영향 버전을 안 쓴다 등) / 만료가 업무 합리 안에 있다 | 사유가 없거나 일반론이다 / 스캔이 `fixed`를 반증하는데 not_affected다 / 결정이 특정 조건 없이 전역 scope를 덮는다 |
| `store_full` (장부 기록) | 위 결정의 원문 그대로 | 미리보기와 기록이 같다 (digest로 강제) | — (미리보기≠기록은 구조적으로 불가능) |
| 챗 HITL 액션 승인 (awaiting_approval) | dock 인라인 승인 버튼 + 토큰 원문 | 버튼 클릭 = 사람의 행위 / 토큰이 이 세션에서 사용자가 실제 입력한 값이다 | 모델이 지어낸 토큰·출처·사유 (BSA-AC-203 — 도구 호출 검증이 드롭한다) |
| `ir advance` (사고 단계 진행) | 현재 단계 + SLA 카드 | 단계가 순서대로다 (전진 전용) / 증거수집 완료가 사실일 때만 analysis 시계가 시작된다 | 뒤로 건너뛰기·거꾸로 진행 (구조적으로 거부됨) / 증거가 안 모였는데 완료로 표시 |
| `reimpl publish` (클린룸 발행) | copy 게이트 측정값 + 테스트 결과 | copy 게이트 0.0 / 생성 테스트가 실제로 통과했다 | 계약 실패인데 재시도로 덮었다 / 원본 식별자·주석이 새 코드에 남아 있다 |

## 심사 공통 원칙 (횡단 판단 5축)

- **결정적 강제** — 토큰 digest 일치·규칙 통과는 코드가 판정한다. 사람은 그 코드 판정을 신뢰할지 말지 고를 뿐, 대신 계산하지 않는다.
- **근거 없는 승인 금지** — "모델이 자신있다"는 데이터가 아니다. 표의 조건에 답 못 하면 보류가 정답이다.
- **기각도 기록** — 기각 시 그 이유가 에스컬레이션/결정 원장에 남는다(루프 닫기: 다음 답변의 reviewer note로 돌아온다).

# GLM IMPLEMENTATION BRIEF 6 — 클린룸 재구현 워크벤치 (시나리오 5번: 아키텍처·엔진 분석 → AI 신규 구현 → 테스트 → publish)

작성: 2026-11-22. 상위 시나리오(사용자 확인): (1) OSS 스캐닝·취약점 분석 → (2) 최선은 OSS 패치 → (3) 단
호환성 리스크 → (4) AGPL/GPLv3는 소스 복제 불가 → **(5) 아키텍처·엔진을 분석해 AI가 신규 코드를 구현,
다이어그램·산출물·요구사항을 리얼타임 표시, 완성 시 단위·통합 테스트 후 publish**. 1~4는 이미 구현
(스캔·패치 게이트·회귀 4분면·council+라이선스 리스크·클린룸 허용 판정). 이 브리프는 5번을 만든다.

## 1. 법적·기술적 근거

- **클린룸 2중 장벽**(전통적 clean-room doctrine, 이 저장소 기록: GPL/AGPL REA 재구현 판정 — "명세 기반
  재구현은 독립 저작물, 어떤 라이선스도 OK / 유사코드 경로는 파생물"). 장벽 1: 리버스 에이전트가 원본을
  읽어 **인터페이스 명세**(시그니처·계약·다이어그램)만 산출. 장벽 2: 생성 에이전트는 **명세만** 입력받는다
  — 원본 소스 텍스트는 프롬프트에 절대 등장하지 않는다(코드가 구조적으로 보장).
- **복제 검출 게이트**: 생성물과 원본의 행 단위 shingle(n-그램) 대조 — 연속 일치율이 임계 초과면 기각.
  클린룸 준수가 "주장"이 아니라 "측정치"로 남는다.
- **라이선스 게이트**: council 판정이 재구현을 막는 경우(허용 목록 밖) 착수 자체를 거부한다.

## 2. 파이프라인 (reimpl.py, 단일 모듈 + 기존 재사용)

| 단계 | 내용 | 재사용 | 이벤트 |
|---|---|---|---|
| A 인터페이스 추출 | stdlib `ast`로 대상 모듈의 public 함수/클래스 **시그니처·docstring 계약**만 추출(구현 본문은 명세에 미포함) | `ast` | `interface_ready` |
| B 명세·다이어그램 | 명세 마크다운(요구사항+계약) + **모듈 의존 DGML**(arch_map 재사용)을 evidence/reimpl/<slug>/에 기록 | `arch_map.to_dgml` | `spec_ready`, `diagram_ready` |
| C 생성 | 장벽 2: 명세 JSON → LLM json_mode로 **신규 코드**(원문 미입력). 오프라인 폴백: 결정론 스캐폴드(시그니처+stub+"scaffold only" 정직 표기) | `llm.ChatClient` | `code_ready` |
| D 복제 게이트 | shingle 대조(기본 임계 0.05) + 라이선스 문자열 스캔(binscan 상수 재사용) | `binscan` 상수 | `copy_gate` |
| E 테스트 | 계약 기반 단위 테스트 생성(결정론: 임포트+시그니처 호출 스모크) + 통합 테스트(임포트 라운드트립) → **격리 서브프로세스** 실행(생성 코드는 비신뢰: 타임아웃·별도 작업복사) | patch 루프 선례 | `tests_running`, `tests_passed/failed` |
| F publish | `deliver.deliver` (branch/folder 기본, inplace는 명시적 허용 플래그 없으면 거부) | `deliver.py` | `published` |

모든 이벤트는 기존 `events.EventBus`+`format_sse`로 스트리밍(작업 단위) — 채팅 스트림·작업 SSE·웹이 같은
관측점을 공유한다.

## 3. 정직성 경계

- LLM 부재 시: 스캐폴드(시그니처+테스트 골격)까지만 — "구현 본문은 LLM 필요"를 결과에 명시.
- 생성 코드 실패/복제 게이트 기각: 부분 결과+갭 주석(4-3차시 오류 봉투)으로 보고, 조용한 성공 없음.
- 명세에 원본 **구현 본문**이 들어가면 클린룸이 깨진다 — 추출기는 시그니처/계약만 내보내는 것이 코드로 강제된다.
- publish 기본값은 branch/folder이고 inplace는 거부(원본 보호) — patch 게이트와 같은 철학.

## 4. AC 계획 (566~571, 등록 시 최대치 재확인 필수 — 병행 세션 상시 선점)

- 566 인터페이스 추출: ast 기반 public 시그니처·계약 추출, 본문 미포함 (추출기 코드 수준 강제)
- 567 명세·다이어그램 산출: spec.md + dependency DGML 기록, spec_ready/diagram_ready 이벤트
- 568 장벽 2 생성: LLM 프롬프트에 원문 미포함(구조 검증) + 오프라인 스캐폴드 폴백의 정직 표기
- 569 복제 게이트: shingle 대조 임계 판정 + 기각 시 정직한 기각 사유
- 570 테스트 레인: 생성 단위·통합 테스트를 격리 서브프로세스로 실행, 성공/실패 부분 결과 보고
- 571 publish: deliver 연동(branch/folder), inplace 거부, published 이벤트

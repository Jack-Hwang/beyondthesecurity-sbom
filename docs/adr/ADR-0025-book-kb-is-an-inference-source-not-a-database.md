# ADR-0025: Book KB는 책 DB가 아니라 서비스 고도화 추론 소스다

## Status

Accepted (2026-11-22, 사용자 지정: "book db는 kw db를 만들라는게 아니라 우리 서비스를 고도화 하는데 추론하라는걸로 쓰이는 거라구")

## 근거 (Context)

Book KB 기능(ADR-0021)은 책 15권을 인제스트해 정제 노트(knowledge_books/, 책 노트 + 기법 노트 59건, "이 프로젝트
적용" 포함, AC-530)와 개선 지도(docs/BOOK_IMPROVEMENT_MAP.md, 전수 매핑)를 이미 만들어 뒀다. 그러나 화면은
수집(ingest)·전문 검색·라이브러리 목록이 위에서부터 차례로 놓인 "책 데이터베이스 브라우저"처럼 생겼고, 사용자는
스크린샷과 함께 목적을 정정했다: 이 지식 베이스는 책/키워드 DB를 구축하는 것이 아니라, **우리 서비스를 고도화하기
위한 추론의 소스**다. 즉 화면이 보여줄 주인공은 책 원문이 아니라 "책에서 우리 서비스로 추론된 적용물"이다.

## 결정 (Decision)

1. **추론 산출물이 화면의 첫 상자**: bts_books.js가 "🧠 우리 서비스 고도화 추론" 상자를 최상단에 놓고 그 안에
   ① 개선 지도(docs/BOOK_IMPROVEMENT_MAP.md를 영역별 표로 파싱: 기법·상태(구현/신규/부분/기각, AC 인용)·근거)
   ② 정제 노트(knowledge_books/*.md를 노트별로 제목·출처 책·핵심 원칙·"이 프로젝트 적용" 불릿으로 파싱)를
   이 순서로 렌더링한다.
2. **두 읽기 API**: GET /api/books/map(지도 파싱)과 GET /api/books/notes(노트 파싱)를 books_api에 추가한다.
   파싱은 books.py의 순수 함수(read_improvement_map / read_notes)가 담당해 노드 하니스 없이 테스트한다.
3. **인프라 재프레밍**: 인제스트 상자는 "노트와 지도가 추론된 원문 소스", 검색 상자는 "추론의 근거를 책 본문에서
   확인"으로 라벨을 바꾸고 그 아래로 내린다. 기능은 그대로다(AC-523..532 유지).
4. **CWD 폴백 금지**: 파서는 root가 비면 정직한 빈 값+힌트를 돌린다 — 절대 프로세스 작업 디렉터리의 실제
   knowledge_books/·docs/를 몰래 읽지 않는다(테스트 더블에서 실데이터 오염 방지).

## 기각 대안 (Rejected alternatives)

- **책 원문 전체를 화면에 펼치는 DB 브라우저 강화** — 저작물 노출 면적만 늘리고(AC-530의 "원문 인용 없음" 원칙과
  반대) 사용자가 말한 목적(서비스 고도화 추론)과 반대 방향이다.
- **챗 라우팅만 바꾸고 화면은 유지** — book_search 답변은 이미 정제 노트를 인덱스에 포함해(AC-529) 적용 관점이
  반영됐다; 문제는 화면의 프레밍이므로 화면을 고친다.
- **개선 지도를 수동 편집 JSON으로 이관** — 문서가 이미 단일 진실 원문이고 표 파싱은 결정론적이다. 이중 원본을
  만들지 않는다.

## 결과 (Consequences)

긍정: Book KB 탭이 제 목적(책→서비스 적용 추론의 보관·전시)을 처음 열면 바로 알린다, 개선 지도의 상태(구현/
기각)가 화면에서 즉시 집계 보이고, 노트 59건의 "이 프로젝트 적용"이 탭에서 탐색된다. 부담: notes/map 파싱이
문서 형식(마크다운 헤딩·표)에 의존해 형식이 흐트러지면 빈 값+힌트로 정직하게 내려간다, root 없는 State 더블의
폴백 금지 규약을 새 API가 지켜야 한다(테스트가 강제).

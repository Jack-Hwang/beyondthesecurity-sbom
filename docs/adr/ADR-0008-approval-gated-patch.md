# ADR-0008: 승인 게이트 패치 (다이제스트 토큰)

## Status
Accepted — 사후 기록. 근거 코드: `bts_sbom_app/patch.py:apply`(토큰 검증), `bts_sbom_app/pipeline.py:_patch_loop`(회귀 시 revert). AC: BSA-AC-14(승인 없는 패치 0건), BSA-AC-15(토큰 불일치 시 변경 0), BSA-AC-18(회귀 시 되돌림), BSA-AC-16(상한 제약). 테스트: `tests/bts_sbom_app/test_patch_delivery.py`.

## 근거 (Context)
"수정해 주면 자동으로 고쳐준다"는 분석 대상 저장소를 변조한다. 이 도구의 정직 계약 2항: "분석 대상 원본은 건드리지 않는다. 푸시·적용은 명시 플래그와 사람 승인 뒤에만".

## 결정 (Decision)
패치 적용은 두 단계다: ① 승인 없이 `patch.apply(approved=False)` → 플랜+다이제스트(16자리 승인 토큰)만 산출, 파일 변경 0. ② 사람이 플랜을 검토하고 토큰을 함께 보내면 워크 복사본에 적용, 재스캔으로 검증, 발견이 늘면 자동 revert. 락파일 직접 수정은 금지(재생성 안내만).

## 기각 대안 (Rejected alternatives)
- 확인 없는 자동 패치: 원본 변조를 도구가 멋대로 한다 — 계약 위반.
- 계획 없는 직접 수정: 검증 가능한 플랜이 없으면 "무엇을 왜 바꿨는지"를 사후에 설명할 수 없다.
- 단순 yes/no 승인: 플랜이 승인 후 바뀌면 오적용 위험 — 다이제스트 토큰으로 플랜 변경을 감지한다.

## 결과 (Consequences)
승인 흐름이 두 번의 호출로 늘어나지만, 모든 변경은 "검토된 플랜의 다이제스트"로 추적되고, 작업 10 이후로는 클라우드에서 승인자 신원까지 기록된다(AC-447).

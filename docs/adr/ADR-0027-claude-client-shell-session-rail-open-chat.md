# ADR-0027: Claude 클라이언트 셸 — 사이드바는 세션 목록, 패널은 접이식, 대화가 주 화면

## Status

Accepted (2026-11-22, 사용자 지시: "여기 메뉴를 주요 기능으로 통합해 기능이 너무 많아. 아니 내말은 claude client
기능으로 따라서 만들라고 했잖아" + CCD 명세 문서 8종 전수 분석 지시)

## 근거 (Context)

데스크탑 셸(ADR-0022) 이후 사이드바에 10~12개 기능 버튼이 평평하게 늘어서 있었다 — 사용자는 스크린샷에 사이드바를
빨간 테로 두르고 "기능이 너무 많다, 주요 기능으로 통합하라"며, 과정 문서(CCD×RFC API·인터페이스 명세서, Code 탭
화면 해부, 디자인·AI 패턴, 생애주기 보강, 보안 하네스, 플랫폼·에이전트 아키텍처 — 모두 전수 분석 완료)를 근거로
"Claude client 기능으로 따라서 만들라"고 정정했다. CCD 명세의 클라이언트 설계는 명확하다: Code 탭 화면은
①사이드바(세션 목록·그룹·고정) ②대화 창 ③패널(diff·터미널·PR·작업·계획·브라우저·아티팩트 — 대화에서 필요 시
열림) ④입력·상태 ⑤다음 단계 상자의 5구역이고(IF-A01), 앱의 기능은 사이드바 메뉴가 아니라 **에이전트가 부르는
제어면 도구(mcp__ccd_*)와 슬래시 명령**(IF-B04·IF-A04)으로 드러난다. BTS-SBOM은 이미 이 절반을 갖고 있었다 —
챗 어시스턴트의 TOOL_CATALOG(20+ 도구)·칩·SSE 스트림·HITL 승인(챗 독)과 12개 기능 판. 빠진 것은 "사이드바가
세션 목록"이라는 점과 "대화가 주 화면"이라는 점이었다.

## 결정 (Decision)

1. **레일 = 세션 목록 우선**: buildSideNav을 Claude 클라이언트 구조로 재작성한다 — 맨 위 ＋ 새 분석(Scan 랜딩),
   분석 세션 목록(/api/history 프로젝트 12건, 클릭=selectProject+Report 판, 선택 하이라이트 — Claude Desktop의
   대화 목록에 해당), 하단 💬 어시스턴트 토글(챗 독 열기+입력 포커스).
2. **기능 패널은 5개 접이식 섹션으로 통합**: 12판을 분석 스캔/결과와 우선순위/리포트와 구조/지식과
   컴플라이언스/수정과 운영의 5개 details 접이식 섹션에 담아 접어 둔다 — 판은 1개도 삭제하지 않는다(26 멤버 전부
   도달 가능). 섹션 헤더가 기존 .rtab[data-sv] 계약을 유지해 activate()/subnav()/GROUPS 로직과 위임 클릭
   핸들러를 무변경으로 둔다.
3. **대화면 기본 펼침**: 챗 독의 초기 상태를 마크업이 결정한다(index.html이 `open` 클래스로 배포 — 접힘은
   사용자가 닫으면 유지). bts_chat_panel.js는 root 클래스에서 초기 상태를 읽는 1줄만 바꾼다. 메시지 영역
   44vh→52vh.
4. **IF-B04 정신의 기존 구현 유지**: 기능-대화 결합은 이미 TOOL_CATALOG·칩·awaiting_approval 승인·diagrams로
   존재 — 이 ADR은 그 결합이 화면의 *주 구조*가 되도록 내비게이션을 재배치하는 것이다.

## 기각 대안 (Rejected alternatives)

- **판을 실제로 삭제/통폐합(기능 제거)** — 모든 판이 실측된 기능(AC 부착)이다. Claude 클라이언트도 기능을
  지우지 않고 패널로 접어 둔다; 삭제는 기능 손실이지 통합이 아니다.
- **챗 독을 파일째 새로 만들어 메인에 이식** — 병행 세션이 같은 파일을 활발히 소유 중(충돌 폭탄), 그리고 독의
  SSE·HITL·mermaid 렌더는 이미 완성품이다. 마크업 클래스+CSS만으로 주 화면화한다.
- **플랫폼 sca_app.js를 고쳐 12탭을 없애는 방향** — 플랫폼 렌더러 무수정 계약(ADR-0022·BSA-AC-542) 위반.

## 결과 (Consequences)

긍정: 첫 화면이 "세션 + 대화"인 Claude 클라이언트 모양이 됐다, 메뉴 인지 부하가 10버튼→5접이식 섹션으로 줄었다,
모든 기능은 여전히 2클릭 안에 있다, 대화가 곧 진입점이 되어 IF-B04의 "기능은 대화가 부른다"가 화면 구조로
실렸다. 부담: 세션 목록은 분석 프로젝트 기준이라 챗 세션과 1:1이 아니다(CCD의 세션=대화와 다른 근사 — 챗
대화 영속화는 별도 과제), 접이식 섹션은 2클릭을 요구한다, 챗 독 기본 펼침은 화면 세로 공간을 더 쓴다(닫으면
유지됨).

# ADR-0028: 대화가 앱을 부른다 — 슬래시 명령·다음 단계 상자·대화 영속화

## Status

Accepted (2026-11-22, 사용자 지시 "계속" — CCD 명세 IF-A04·IF-B04·CL-12의 클라이언트 구현, ADR-0027 후속)

## 근거 (Context)

ADR-0027로 화면 구조는 Claude 클라이언트(세션 레일·대화 주화면·접이식 판)가 됐지만, CCD 명세의 나머지 절반 —
기능 구동 계약 — 은 아직 부분이었다. IF-A04(슬래시 명령 `/code-review` 등)와 IF-B04(앱이 자기 기능을 에이전트에
MCP 제어면 도구 `mcp__ccd_<group>__` 로 노출 — session/sidebar/view/turn 등)는 "사용자와 에이전트가 모두 같은
앱 기능을 부른다"는 원칙이고, Code 탭 zone 5는 턴 마무리마다 "다음 단계 상자"(요약·결정 질문·버튼)를 요구한다.
또 CL-12 Local Data Store는 세션 기록을 로컬에 두는(CCD는 30일 보관) 대화 영속화를 전제한다. BTS-SBOM의 챗
어시스턴트는 도구 20+종으로 서비스를 조회하지만, 판을 여는 것은 전부 수동 내비게이션이었고 대화는 새로고침하면
사라졌다.

## 결정 (Decision)

1. **슬래시 명령(IF-A04 클라이언트 구현)**: 대화 입력을 `/^\/([a-z]+)\b/` 로 먼저 검사한다. 15개 판 명령
   (/oss /report /risk /prioritize /arch /code /diagrams /books /compliance /vex /fix /history /fleet /findings
   /scan)은 `bts:activate` 커스텀 이벤트로 판을 열고 — **모델 호출 0회**. `/scan <대상>`은 Scan 랜딩 입력을 채우고
   ▶ Analyze 버튼을 클릭해 통합 파이프라인(ADR-0026)까지 실행한다. `/help`는 명령 목록, 알 수 없는 명령은 모델로
   넘기지 않고 "모르는 명령" 안내로 끝낸다 — 실수로 LLM 예산을 쓰는 일이 없다.
2. **다음 단계 상자(CCD zone 5)**: 턴의 `tool_call` 이벤트에서 실제 실행된 도구를 수집하고(NEXT 매핑 12종),
   final 렌더링 아래에 대응 판 보기 버튼을 제안한다. 제안 근거는 그 턴이 실제로 도네 도구뿐 — 없으면 상자도 없다.
3. **대화 영속화(CL-12 아날로그)**: `bts-chat-<프로젝트>` 키로 localStorage에 저장(이 브라우저 한정, 서버 전송
   없음), 프로젝트 전환 시 저장→교체→복원 — 전환 감지는 selectProject가 발행하는 bts:project 커스텀 이벤트 단일 지점(레일 세션·히스토리 자동 선택 등 프로그래매틱 전환은 change 이벤트가 없다). 저장 시 승인 버튼(.bts-cd-approve)과 다음 단계 버튼은 잘라낸다 —
   리스너 없는 죽은 컨트롤이 사람을 속이지 않게. 스토리지 쓰기 실패는 예외가 아니라 "영속되지 않는 대화"로 끝난다.
   프로젝트별 ⌫ 지우기 버튼 제공.

## 기각 대안 (Rejected alternatives)

- **서버 채팅 도구로 판 전환 구현(TOOL_CATALOG에 open_panel 추가)** — 판 전환은 순수 클라이언트 상태인데 왕복
  LLM 호출로 하면 예산·지연만 쓴다. CCD도 제어면 도구는 앱 로컬(IF-B04, 서버 아님)이다.
- **대화 전체(활동 카드 포함) 영속화** — 활동 카드는 턴 재생산물이고 승인 토큰은 1회성이다. 죽은 승인 버튼이
  남는 쪽을 택하지 않고 응답+사용자 줄만 저장한다.
- **서버 세션 저장(Redis·DB)** — 로컬 전용·인증 없는 이 서비스의 위협 모델에서 불필요한 수집이고, CCD의
  CL-12도 로컬 저장이 기본이다.
- **단축키(Cmd+Shift+M 등) 동시 구현** — 웹 클라이언트의 키 충돌(브라우저 예약) 검증이 먼저다. 필요해지면 별도.

## 결과 (Consequences)

긍정: 판 전환·스캔 실행이 대화에서 끝난다(모델 예산 0), 턴이 끝나면 다음 행동이 버튼으로 제안된다, 새로고침·
프로젝트 전환 후에도 대화가 돌아온다. 부담: 슬래시 테이블과 NEXT 매핑은 판 추가 시 수동 갱신(테스트가 수 세고
강제), localStorage는 지워질 수 있고 기기 간 동기화가 없다(CCD 30일 로컬 기록과 같은 한계), 저장본 innerHTML
복원은 같은 출처 렌더링 산출물에 한한다.

# C / C++ 지원: 클린룸 재구현 + 호환성 게이트 (AC-637~644)

오픈소스의 대부분은 C/C++다. 이전 구현은 Python(`ast`)에만 묶여 있었다. 이제 같은 두 기능이 C/C++에서 **실제 컴파일러**로 검증된다.

## 구성

| 모듈 | 역할 |
|---|---|
| `cparse.py` | 표준 라이브러리 전용 C/C++ 선언 리더(함수·타입·매크로·열거 값·변수·doc 주석, **본문은 저장하지 않음**) + 프로젝트 사용 스캐너(호출 인자 수, 매크로/상수/타입/필드 참조) |
| `reimpl_c.py` | 클린룸 C/C++ 백엔드. `reimpl.reimpl()`이 `.c/.cc/.cpp` 확장자에서 자동 분기(같은 레코드·같은 SSE 이벤트) |
| `compat_c.py` | C/C++ 호환성 게이트. `compat.assess()`가 C 계열 생태계/`language` 필드에서 분기 |

## 클린룸 레인 (재구현)

1. **벽 1 — 리더**: 컴포넌트와 짝 헤더에서 인터페이스(프로토타입, 계약 주석, 필요한 타입/매크로/데이터)만 추출. 본문은 파서가 보관하지 않으므로 나갈 수 없다.
2. **헤더**: 선언 모델에서 **결정적으로** 렌더링(생성기는 원본 헤더를 보지 못하고 헤더를 쓰지도 않는다). 전방 선언·의존 순서·커널식 정수 typedef(`u8`, `__u32`…)로 자급자족.
3. **벽 2 — 생성기**: 명세만 받아 새 `<module>.c`를 반환.
4. **복사 게이트**: 함수 **본문**의 식별자 정규화 토큰 겹침(이름만 바꾼 복사도 잡음) + 주석 제거 줄 겹침. API 프로토타입·숫자 테이블(CRC/CTYPE 같은 수학적 사실)은 증거에서 제외. 60토큰 미만 본문은 `reliable:false`.
5. **컴파일 게이트**: 실제 gcc/clang(`-Wall -Wextra`, 암시적 선언은 에러) + `nm`으로 API 심볼·공개 테이블 내보내기 증명.
6. **오라클**: ① 원본 테스트 `main`을 새 모듈에 컴파일·실행 ② **차등 드라이버** — 이 호스트에서 원본을 컴파일(심볼을 `orig_*`로 치환)하고, 경계 정수·랜덤 버퍼·문자열·입출력 버퍼로 원본과 새 코드를 호출해 반환값과 출력 메모리를 비교. 공개 배열 변수는 바이트 단위 비교. 실패 케이스는 **관찰된 사실**로 생성기에 되돌아가 1회 재생성.
7. **판정**: `ok`(오라클 통과) · `compatibility_failed` · `rejected`(복사) · `tests_failed`(컴파일/내보내기) · **`contract_only`**(컴파일·내보내기는 됐으나 오라클 없음 — 동작 미검증, 절대 ok 아님) · `toolchain_missing`.

### 원본을 낯선 호스트에서 빌드하기

커널 스타일 코드(u-boot)는 Windows/mingw에서 그대로 컴파일되지 않는다. 오류별 보수 규칙: 프로젝트 include를 시스템 헤더 **뒤**(`-idirafter`)로, 호스트 타입(`size_t`…)이나 libc 함수를 재정의하는 프로젝트 헤더는 **가장 구체적인 include 철자**로 빈 스텁 대체, `typedef` 줄의 미지 타입은 정수 typedef, `__rcode` 같은 마커 단어와 `IS_ENABLED(...)` 류는 무력화, 그래도 안 되면 짝 헤더를 렌더링한 헤더로 **그림자 대체**.

## 실측 (u-boot v2026.10, GPL-2.0+, 이 Windows 호스트, gcc 16.2)

| 항목 | 결과 |
|---|---|
| 선언 리더 vs Universal Ctags | 헤더 625개 recall **0.997** / precision **0.998**, `lib/*.c` 83개 0.991 / 1.000, 크래시 **0** |
| `lib/crc8.c` (실제 GPL 코드) | 독립 구현 → 원본을 독립 빌드해 **함수 2·132케이스 불일치 0** → `ok` |
| `lib/crc16.c` | 함수 + 256항목 테이블. 정확한 테이블 `ok`; **테이블 한 항목이 틀리면 오라클이 잡고 재생성 후 `ok`** |
| 복사 게이트 | 이름만 바꾼 복사 토큰 겹침 **1.0 → rejected**; 독립 구현 0.06; CRC 테이블 행은 증거에서 제외(처음엔 줄 겹침 0.88로 오탐 → 수정) |
| **오라클 커버리지(정직)** | `lib/` 외부 함수가 있는 77개 중 원본이 독립 빌드되는 것 **13개(17%)**, 비교 가능 함수가 있는 것 **11개**(19함수). 렌더링 헤더 단독 컴파일 57/77 |

나머지 파일은 u-boot의 Kconfig/보드 설정에 깊이 의존해 `contract_only`가 된다. 이는 도구의 한계가 아니라 **그 코드를 설정 없이는 실행할 수 없다는 사실**이며, 판정에 그대로 드러난다.

## 호환성 게이트 (C/C++)

패치 대상 라이브러리의 **현재/대상 릴리스 공개 헤더**(provider: 디렉터리·git 태그·tarball)를 비교한다.

* **breaking**: 제거된 함수/매크로/열거자/변수, 호출 인자 수가 대상 프로토타입(또는 함수형 매크로)에서 거절되는 호출, 프로젝트가 읽는 구조체 필드의 제거(이름 일치).
* **review**: 상수/열거 값 변경, 매개변수/반환 타입 변경, 구조체 레이아웃 변경(ABI), 신규 deprecated.
* **컴파일러 차등**: 라이브러리를 include하는 프로젝트 소스를 구/신 헤더로 각각 `-fsyntax-only`; **신 헤더에서만** 생기는 에러가 측정된 파손(양쪽에 있는 에러는 상쇄). 헤더 차이와 컴파일러가 독립적으로 같은 파손을 확인한다(픽스처: 구 0 → 신 6 에러).
* 정직 규칙은 Python과 동일: 헤더/제공자 없음 → `unverified`, 사용 없음 → `not_direct`, 절대 보류하지 않음.

## 한계 (정직하게)

* 헤더는 **전처리하지 않고** 읽는다(`#if` 분기 전부 포함); 필드 접근은 **이름 일치**(타입 추론 없음); 바이너리/SONAME ABI 분석 없음.
* 차등 드라이버는 스칼라/버퍼/문자열 인자만 만든다(구조체·함수 포인터 인자는 "비교 불가"로 집계). 동일 출력은 증거이지 증명이 아니다.
* C++ 클래스는 컴파일 검증만(차등 드라이버는 자유/네임스페이스 함수).
* 모델이 다른 곳에서 학습한 GPL 코드를 재현할 수 있다: 복사 게이트는 **주어진 원본과의 겹침**만 측정한다.
* 엔진의 C/C++ 의존성 발견(Conan/vcpkg)은 아직 얇다 — 게이트는 생태계 이름에 의존하지 않고 헤더 provider를 주입받는다.
* 헤더 provider 기본 구현은 디렉터리와 git 태그. 레지스트리별(Conan Center 등) 자동 해석은 아직 없다.

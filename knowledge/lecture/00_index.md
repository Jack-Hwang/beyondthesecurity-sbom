# 강의자료 색인

출처: `강의자료/`(PDF 9 + zip 4). 무엇을 다루는지·중요 페이지·BTS-SBOM 관련도만 요약한다. 기법 상세는 각 digest 파일에 있다.

## PDF 9종

**1주차_1차시_통합아키텍처설계.pdf(43p)** — Azure 호스팅 선택, Azure OpenAI 연동, 에이전틱 5대 결정, ADR 작성. 핵심: p.7-22(에이전틱 결정), p.38(ADR 템플릿). **관련도 중간** — Azure 인프라는 적용 불가, ADR 규율만 `sdd_and_requirements.md`에 반영.

**1주차_2차시_컨테이너AI챗봇.pdf(41p)** — 종료신호 기반 툴 루프, 공회전 탐지, case facts, 컨텍스트 예산, 컨테이너 배포. 핵심: p.7-10, 21-29. **관련도 높음** — `chatbot_and_agents.md`의 핵심 원전. 컨테이너 부분 제외.

**1주차_3차시_요구사항분석_주제선정.pdf(38p)** — EARS 5패턴, 요구 분류 코드, SDD 10섹션, 명시적 기준 테스트, 인터뷰 패턴, 주제 선정 매트릭스. 핵심: p.5-26 전반. **관련도 높음** — `sdd_and_requirements.md`의 뼈대.

**2주차_1차시_DataOps_MLOps.pdf(30p)** — Ops 3종 구분, 성숙도 0~2단계, CI 게이트, 헤드리스 실행, Batches API, 평가 루프 4지표. 핵심: p.5-20. **관련도 높음** — `dataops_mlops_loop.md` 직결. Batches API는 EXAONE에 적용 불가.

**2주차_2차시_학습데이터파이프라인.pdf(42p)** — 비식별화, 스키마 강제 라벨링, 검증 4계층, 신뢰도 보정, 층화표집. 핵심: p.9-31. **관련도 높음** — 검증 4계층이 baseline "4-layer validator"와 거의 1:1 일치(교차검증).

**2주차_3차시_HybridSearch_고급RAG.pdf(37p)** — BM25/벡터/RRF/리랭킹, 계층 청킹, 쿼리 변환, 출처 보존(claim-quote-source-date), 상충 처리, 검색/생성 지표 분리. 핵심: p.5-26 전반. **관련도 매우 높음** — `rag_methods.md`의 핵심 원전. baseline의 RRF k=60과 공식이 정확히 일치.

**별첨_AI에이전트_답변품질_평가지표·방법론_TOP10.pdf(25p)** — 답변품질 10대 지표(정답도~온라인회귀게이트)를 공식·임계값·자동화 코드로 정리. 핵심: 전체, 특히 p.24-25(스코어카드). **관련도 매우 높음** — `eval_metrics.md`의 핵심 원전. 회귀게이트 공식(Δ≥−δ, δ=0.02)이 baseline과 정확히 일치.

**별첨_LLM·RAG·파인튜닝·AI에이전트_아키텍처_종합해설.pdf(30p)** — LLM 내부구조·수식, RAG/GraphRAG/Agentic RAG 비교, LoRA 5기법, 에이전트 9요소, 엔터프라이즈 시스템 선택. **관련도 낮음~중간** — 대부분 일반 교양 인포그래픽 해설. RAG 에스컬레이션 판단 규칙(p.15,19)만 `rag_methods.md`에 짧게 인용. LoRA 파인튜닝(p.20-23)은 **적용 불가**(EXAONE은 API 호출만, 로컬 파인튜닝 대상 아님). 엔터프라이즈 20시스템 선택(p.27-29)도 범위 밖.

**Azure 2건 + .docx 1건 — 제외**: `Azure In Open 볼륨 라이선스 활성화 가이드.pdf`, `애저 크레딧 등록 오류 지원 방법1/2.pdf`는 Azure 계정 등록 UI 조작 가이드(스크린샷 위주, 방법론 없음) — **관련도 없음**. `아로새김_접수양식_작성본_v10_UI update_.docx`는 본 과정과 무관한 타 공모전(현대자동차그룹 차량용 앱 개발 공모전) 참가신청서이며 참가자 개인정보가 포함돼 있어 내용을 옮기지 않았다 — **관련도 없음, 오분류 추정**.

## zip 4종

**adv-lab.zip(768개 항목)** — 6주차 실습 스타터(`w1-1`~`w6-x`, `init/learning/complete`)와 레퍼런스 프로젝트 `ref-project/`(SDD 전체, `.claude/` 하네스). 과제 범위인 `w1-1~w1-3`·`w2-1~w2-3`의 `init/`(함수 시그니처+docstring, 구현은 빈 연습문제)를 읽어 설계 의도를 확인했다. `ref-project/sdd/`는 SDD 디렉터리 구조 실물 예시로 `sdd_and_requirements.md`에 반영. **관련도 높음(1~2주차), 미확인(3~6주차 — 범위 밖).**

**prompt.zip / 실습자료.zip** — 주차별 "실습 프롬프트" 마크다운. `2주차_실습_프롬프트.md`를 정독했으며 PDF의 S1~S6 게이트를 구현 수준까지 구체화한다(예: RAG 로컬 폴백 = `rank_bm25`+로컬 임베딩+코드 RRF+크로스인코더 — Azure 없이 재현 가능해 BTS-SBOM의 stdlib-only 제약과 직접 맞닿음). 0·1·3~6주차 파일은 범위 밖이라 열지 않았다. **관련도 높음(2주차), 미확인(나머지).**

**과제가이드.zip(HTML 6개)** — 과제1~5 제출 가이드 + 포트폴리오 가이드. `과제1_가이드.html`만 정독: 채점 루브릭(AC정의20·구현게이트40·설계근거20·문서증빙20)을 `sdd_and_requirements.md`의 참고 배점 모델로 인용했다. 나머지는 Azure 과금·제출 절차 위주라 방법론 중복이 많아 열람하지 않았다. **관련도 낮음~중간(루브릭만 차용).**

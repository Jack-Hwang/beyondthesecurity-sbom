# 답변 품질 평가 — 지표·방법론과 EXAONE 100회/일 제약

원전은 별첨 "AI에이전트 답변품질 평가지표·방법론 TOP10"[별첨_AI에이전트_답변품질_평가지표·방법론_TOP10.pdf]이며, 지표마다 2쪽(개념/개요 1쪽 + Workflow·자동화 1쪽)으로 구성되어 있다. baseline은 이미 Recall@5·MRR(15개 골든셋+5개 OOD)과 regression gate(delta>=-0.02)를 쓰고 있으므로, 아래는 그 틀에 무엇을 더하거나 이미 일치하는지를 중심으로 정리한다.

## 평가 체계의 3축 (무엇을 고를지 먼저 정하는 틀)

평가 방법은 ①정답 참조 필요 여부 ②채점자(코드 → LLM 심사 → 사람, 오른쪽일수록 비용·유연성 ↑) ③시점(오프라인 골든셋 vs 온라인 운영 트래픽)의 3축으로 고른다 [별첨_TOP10 p.3]. BTS-SBOM는 EXAONE 호출이 하루 100회로 제한되므로, 이 3축 중 "코드 채점"을 최대한 넓히고 "LLM 심사"는 코드로 잴 수 없는 항목에만 아껴 써야 한다.

## 10대 지표/방법론 — 정의·임계값·채점 수단

| # | 지표 | 정의(핵심) | 예시 임계값 | 정답 참조 | 코드만으로 채점 가능? |
|---|---|---|---|---|---|
| ① 정답도 | 정답 참조와 핵심 사실 일치 여부. 채점기 EM→F1→의미유사도→LLM심사 순으로 유연 | 정답률 ≥ 0.85 | 필요 | 사실·추출형은 가능(EM/F1), 서술형은 LLM심사 필요 |
| ② 근거성·환각 | 답변을 주장 단위로 쪼개 각 주장이 컨텍스트에서 지지되는지. F=지지주장/전체주장 | Faithfulness ≥ 0.90 | 불필요 | 주장 분해 자체가 LLM 의존(완전 코드화 어려움) |
| ③ 관련성·완결성 | 역생성 질문과 원질문의 코사인 유사도(관련성), 필수요소 충족률(완결성) | 관련성≥0.80, 완결성≥0.90 | 불필요 | 관련성은 임베딩만 있으면 코드로 가능, 완결성은 요소 목록 설계가 필요 |
| ④ 검색품질 | Recall@k·MRR·nDCG@k(IR) + Context Precision/Recall(RAG) | Recall@5≥0.85 | 필요(gold 문서) | **완전히 코드로 결정적 계산 가능** |
| ⑤ 툴호출정확도 | 기대 툴호출과 실제 호출을 이름·인자·순서로 비교. TCA=일치/전체 | 읽기≥0.95·쓰기=1.0 | 필요 | **완전히 코드로 계산 가능**(트레이스만 있으면) |
| ⑥ 궤적·과제완수 | 목표상태 달성 여부 + 궤적 비교(strict/unordered/subset/superset) + pass^k | 완수율≥0.80, pass³≥0.70 | 필요 | 목표상태 검사는 코드 가능, 궤적 비교 모드 선택은 설계 필요 |
| ⑦ 안전성·정책준수 | 공격성공률(ASR)=성공한 공격/전체 공격, 과잉거절률 | 치명 0건, ASR 0 | 불필요 | 규칙(PII 패턴 등) 기반이면 코드 가능 |
| ⑧ LLM-as-a-Judge | 루브릭 받은 LLM이 점수+이유로 채점, 사람 대비 일치도로 검증 | 일치도≥0.80·κ≥0.60 | 상황별 | 채점 자체는 LLM 필요, 신뢰 여부 검증은 코드(Cohen's κ) |
| ⑨ 사람평가·선호비교 | 이중 블라인드 라벨 + Cohen's κ + Elo/Bradley-Terry 순위화 | κ≥0.60 | 상황별 | 집계는 코드, 라벨링은 사람 |
| ⑩ 온라인평가·회귀게이트 | Δ=score_cand−score_base ≥ −δ | δ=0.02(예시) | 필요(기준 버전) | **완전히 코드로 계산 가능** |

## EXAONE 100회/일로 측정 가능한 것 vs 불가능한 것

**코드만으로(EXAONE 호출 0회) 측정 가능**: ④검색품질(Recall@k/MRR/nDCG@k, Context P/R — gold 라벨만 있으면 됨), ⑤툴호출정확도(함수 호출 트레이스 비교), ⑦안전성 중 규칙 기반 항목(PII 패턴 탐지, 금지어 매칭), ⑩회귀게이트(Δ 계산 자체), ①정답도 중 사실·추출형(EM/F1/정규화 비교), ③관련성 중 임베딩 코사인 유사도 부분(단, 임베딩 모델이 로컬에 있어야 함 — BTS-SBOM가 TF-IDF 벡터를 이미 쓰므로 OpenAI 임베딩 대신 TF-IDF 코사인으로 대체 가능).

**LLM 호출이 필요(EXAONE 예산을 쓴다)**: ②근거성의 "주장 분해"(단, BTS-SBOM는 verbatim-substring 인용을 강제하므로 이 단계를 **코드로 우회**할 수 있다 — claim이 코퍼스의 정확한 부분 문자열이어야 한다는 baseline 규칙 자체가 "환각 없는 근거성"의 결정적(deterministic) 프록시다), ①정답도의 서술형 채점, ⑥궤적 평가의 궤적 비교 판정, ⑧LLM-as-a-Judge 전반.

### BTS-SBOM 적용 — 권장 지표 세트
1. **nDCG@5 추가**(코드, 호출 0회): baseline의 Recall@5·MRR 옆에 세 번째 검색 지표로 추가. gold 문서가 이진 관련도이므로 별도 라이브러리 없이 계산 가능.
2. **회귀 게이트에 4지표 명시화**(코드, 호출 0회): 현재 "delta>=-0.02" 하나로 뭉쳐 있는 것을 통과율·회귀율·지연·평가당 EXAONE 호출 수 4개로 분리해 리포트한다 — "평가당 비용"을 "평가당 EXAONE 호출 수"로 바꾸면 하루 100회 예산 관리에 직접 쓰인다 [2주차_1차시_DataOps_MLOps.pdf p.19].
3. **LLM-as-judge를 쓰기 전에 Cohen's κ로 먼저 검증**(호출 필요, 그러나 1회성 비용): EXAONE을 채점기로 쓰려는 모든 새 지표(예: 서술형 정답도)는 먼저 사람이 라벨링한 소규모 샘플(예: 30문항)에 대해 EXAONE 채점과 사람 라벨의 일치도(κ)를 재고, κ≥0.6 미만이면 그 지표를 "사용 중지"하고 코드 기반 대체 지표로 되돌린다. 이는 baseline에 없는 안전장치이며, 월 1회 또는 EXAONE 모델이 바뀔 때만 재보정하면 되므로 하루 100회 예산을 거의 쓰지 않는다 [별첨_TOP10 p.19].
4. **안전성 지표(ASR) 신설**(코드, 호출 0회): RAG 코퍼스에 "이전 지시 무시" 류 간접 프롬프트 주입 공격 문서를 넣는 회귀 테스트 세트를 만들고, 규칙 기반(패턴 매칭)으로 공격 성공률을 측정한다. 목표: 치명 0건. PR마다 스모크 수십 건, 분기마다 전체 실행 — 전부 코드로 가능해 EXAONE 예산을 쓰지 않는다 [별첨_TOP10 p.16-17].
5. **적용 불가**: ⑥궤적·과제완수(pass^k, 멀티턴 시뮬레이션 사용자)는 BTS-SBOM가 멀티턴 대화형 에이전트가 아니라 단발 질의-응답 RAG이므로 해당 사항 없음. ⑨사람평가·Elo 순위화는 평가자 풀이 없는 1인/소규모 팀 개발 환경에는 과함 — 적용 불가(사람 평가자 부재).

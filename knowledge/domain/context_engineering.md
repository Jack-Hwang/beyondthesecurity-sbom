# 컨텍스트 엔지니어링 (Rothman 개념 요약)

Denis Rothman 의『Context Engineering for Multi-Agent Systems: Move beyond prompting to build a Context Engine』(Packt) 에서 다루는 개념을 BTS-SBOM 팀이 정리한 요약이다(원문 인용이 아니라 개념의 재서술이다).

## 프롬프트에서 컨텍스트 엔진으로

LLM 을 쓰는 시스템의 품질은 프롬프트 문구가 아니라 "무엇을 컨텍스트로 넣는가"로 결정된다. Rothman 은 컨텍스트의 성숙도를 단계로 본다: (1) 맨 프롬프트, (2) 선형 컨텍스트(관련 자료 나열), (3) 목표 지향 컨텍스트, (4) 역할 기반 컨텍스트, (5) 의미 청사진(semantic blueprint) — 입력에서 역할·관계·의도가 구조화된 표현. 좋은 컨텍스트는 작고(role-relevant), 구조화되고, 검증 가능해야 한다.

## 컨텍스트 인지 다중 에이전트

복잡한 작업은 전문화된 에이전트(계획자/planner, 도구 실행자, 검증자, 요약자)로 나누고 오케스트레이터가 조율한다. 핵심 장치: MCP 같은 도구 프로토콜로 에이전트가 도구를 표준화된 방식으로 호출, 컨텍스트 체이닝(한 단계의 산출이 다음 단계의 컨텍스트 입력이 됨), 동적 계획(planner가 작업 분해), 컨텍스트 축소(summarizer agent로 긴 히스토리를 요약해 토큰·노이즈를 줄임).

## 프로덕션 경도(hardening)

프로토타입을 운영 시스템으로 만들기 위한 관행: 모듈화(모놀리식 노트북 → 재사용 라이브러리), 구조화된 로깅, 의존성 주입, 오류 처리, 검증 레이어(에이전트 출력을 스키마·규칙·근거로 검증하고 실패 시 안전한 폴백), 응답 지연·콘텐츠 정책(모더레이션), 고신뢰 RAG(검색된 근거로만 답하고 인용을 검증), 투명성(어떤 컨텍스트와 도구가 쓰였는지 추적 가능).

## BTS-SBOM 적용 관점

이 프로젝트의 LLM 레인은 같은 원칙을 따른다: (1) Arch Intel 프롬프트는 원본 코드 없이 메타데이터만 담은 구조화 증거 = 의미 청사진의 축소판, (2) AI 출력은 4계층 검증 + 근거 그라운딩 + 실패 시 결정론 폴백 = hardening의 검증 레이어, (3) 챗봇은 검색 근거(verbatim 인용)로만 답하는 grounded RAG, (4) 프롬프트 해시 캐시와 일일 예산으로 비용을 관리한다. 다중 에이전트 분해(분석 에이전트와 검증 에이전트의 분리)는 도입 여지가 있는 다음 단계다.
